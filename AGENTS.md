# AGENTS.md

> Карта репозитория для агентов и новых разработчиков. Поддерживается вручную
> и при существенной перестройке структуры обновляется. Подробностей отсюда
> не разворачивать — они лежат в `.ai-factory/DESCRIPTION.md`.

## О проекте

`verdeect/identity-laravel` — библиотека Composer, связывающая продукт
установки Verdeect с Identity Service: вход по потоку кода с PKCE, токены,
профиль, разрешение имён, данные кросс-сервисной навигации и потребление
сообщений установки. Схема Backend-for-Frontend: токены живут на сервере
и наружу не выходят.

**Это библиотека, а не приложение.** Своего `app/`, базы данных, миграций
и фронтенда здесь нет и не будет.

## Технологический набор

- **Язык:** PHP 8.3
- **Каркас:** Laravel 13 (`illuminate/support`, `illuminate/http`) как
  зависимость библиотеки
- **База данных:** нет — пакет в неё не пишет
- **ORM:** нет
- **JWT:** `web-token/jwt-library` 4
- **Брокер:** `php-amqplib/php-amqplib` 3
- **Хранилище:** Redis через штатный кэш Laravel; в прогоне — `array`
- **Прогон:** Pest 5 + orchestra/testbench 11
- **Статический разбор:** PHPStan + Larastan, уровень 7

## Структура

```
├── config/
│   └── identity.php     единственный файл настройки; публикуется группой identity-config
├── routes/
│   └── identity.php     маршруты входа, возврата и выхода, группа web
├── src/
│   ├── Api/             клиенты прикладного интерфейса установки и их DTO
│   ├── Discovery/       документ обнаружения, JWKS, проверка ID-токена
│   ├── Events/          потребитель RabbitMQ, отправка обработчику, отметки гашения
│   ├── Exceptions/      отказы интеграции, общий предок IdentityException
│   ├── Flow/            начало потока кода авторизации, пара PKCE
│   ├── Http/            контроллеры, middleware, внешнее перенаправление
│   ├── Inertia/         сборка разделяемых свойств для интерфейса
│   ├── Profile/         профиль пользователя, формы имени, точка расширения
│   ├── Rights/          роль и ограничения вошедшего из текущего токена
│   ├── Session/         чтение сессии входа
│   ├── Support/         настройка, кэш, HTTP-клиент, вычисление origin
│   ├── Tokens/          хранилище, обмен, выдача действующего токена
│   └── IdentityServiceProvider.php   единственный провайдер; все привязки здесь
├── testing/
│   └── helpers.php      оснастка прогонов; уходит в поставку через autoload.files
├── tests/
│   ├── Feature/         наборы поверх контейнера testbench
│   └── Unit/            наборы отдельных вычислений
└── .ai-factory/         контекст агентов: спецификация, архитектура, правила
```

## Точки входа

| Файл | Назначение |
|---|---|
| `src/IdentityServiceProvider.php` | регистрация привязок, маршрутов, команды и публикуемой настройки |
| `config/identity.php` | все настраиваемые значения; адресов эндпоинтов здесь нет намеренно |
| `routes/identity.php` | `/auth/login`, `/auth/callback`, `/auth/logout` |
| `src/Events/ConsumeIdentityEventsCommand.php` | команда `identity:consume-events` |
| `src/Inertia/IdentityProps.php` | сборка разделяемых свойств, вызывается продуктом |
| `src/Support/IdentityOrigin.php` | origin установки для политики содержимого продукта |
| `testing/helpers.php` | поддельная установка identity для наборов пакета и продукта |
| `composer.json` | `composer test`, `composer types:check`, `composer ci:check` |
| `Makefile` | короткий вход к тем же проверкам плюс фильтр, покрытие и проверка манифеста; `make help` |
| `phpunit.xml` | окружение прогона; из окружения разработчика не берётся |
| `phpstan.neon` | уровень 7, разбираются `src` и `testing` |

## Правила для агентов

- **Команды оболочки не склеивать** через `&&`, `||` и `;` — каждая
  выполняется отдельным вызовом. Склейка ломает проверку разрешений
  в `settings.json`: каждая команда обязана проверяться сама по себе.
  - Неверно: `git checkout main && git pull`
  - Верно: сначала `git checkout main`, затем `git pull origin main`
- **Границы пакета не обсуждаются.** Ни одного упоминания `App\` в `src/`;
  ни имён очередей, ни селекторов разметки, ни адресов конкретной установки
  в коде — только настройка либо параметр.
- **Компоненты интерфейса здесь не заводить.** Рейл навигации и блок
  пользователя живут в npm-пакете `@verdeect/identity-nav-vue`.
- **Скиллы, рассчитанные на приложение**, к этому репозиторию неприменимы:
  модулей, Eloquent-моделей, миграций и Vue тут нет.
- **Перед сдачей** — `composer ci:check`. Уровень PHPStan не снижается,
  предупреждения не подавляются.
