# Данные пользователей

Три разных источника, и путать их нельзя: **свой** профиль приходит из
`/userinfo` пользовательским токеном, **чужие** имена — из `/api/users/resolve`
служебным, данные рейла — из `/api/users/services` тоже служебным.

## Идентификатор пользователя

В своих таблицах продукт хранит **`sub`** — ULID из 26 знаков.

**Снимок имени не сохраняется.** Удаление учётных записей в установке
запрещено, поэтому идентификатор остаётся разрешимым всегда, а сохранённое имя
устаревает молча.

**Связывание по адресу электронной почты недопустимо:** адрес изменяем,
`sub` — нет.

```php
// Схема таблицы продукта
$table->string('actor_sub', 26)->index();
```

## Профиль текущего пользователя

```php
use Verdeect\IdentityIntegration\Profile\ProfileProvider;

$profile = app(ProfileProvider::class)->current();   // UserProfile|null
```

| Поле | Содержимое |
| --- | --- |
| `sub` | идентификатор |
| `name` | полная форма как есть |
| `givenName`, `familyName`, `middleName` | части имени |
| `shortName` | имя и фамилия через пробел |
| `initials` | первые буквы имени и фамилии, заглавными |
| `locale` | язык интерфейса владельца |

Кэшируется и сбрасывается сообщением `user.profile.changed`.

`currentDecorated()` возвращает тот же профиль массивом, пропущенным через
[точку расширения](extensions.md) — именно её результат уходит в разделяемые
свойства Inertia.

**ID-токен для получения имени не используется.** Он служит ровно двум вещам:
проверке `nonce` при входе и подсказке `id_token_hint` при выходе. Извлекать
из него ФИО недопустимо — он фиксирует момент входа и свежим не поддерживается.

## Формы имени

| Форма | Правило |
| --- | --- |
| Полная | `name` как есть |
| Краткая | `givenName`, пробел, `familyName` |
| Инициалы | первая буква `givenName` и первая буква `familyName`, заглавными |

Срез первой буквы **многобайтный**: однобайтный дал бы половину символа.
Отчество в инициалах не участвует.

Формы считает пакет — продукту достаточно взять готовые поля. Если нужно
собрать их из частей самому:

```php
use Verdeect\IdentityIntegration\Profile\NameForms;

NameForms::short($givenName, $familyName);
NameForms::initials($givenName, $familyName);
```

## Разрешение чужих имён

```php
use Verdeect\IdentityIntegration\Api\IUserResolver;

/** @var array<string, ResolvedUser> $resolved */
$resolved = app(IUserResolver::class)->resolve($subs);
```

| Поле `ResolvedUser` | Содержимое |
| --- | --- |
| `sub` | идентификатор запроса |
| `name`, `shortName`, `initials` | формы имени |
| `isResolved` | `false`, если установка не знает такого идентификатора |

### Обращение только пакетное

**Вызов в цикле по строкам списка — ошибка реализации.** Тридцать записей дали
бы тридцать обращений к установке, а при её недоступности — тридцать ожиданий
подряд.

Правильный приём — собрать идентификаторы всей страницы, разрешить одним
вызовом, разложить по строкам:

```php
$subs = array_values(array_unique(array_map(
    static fn (ChangeLogEntry $entry): string => $entry->actor_sub,
    $entries,
)));

$resolved = $this->users->resolve($subs);

return array_map(
    static fn (ChangeLogEntry $entry): ChangeLogEntryDto => ChangeLogEntryDto::fromEntity(
        $entry,
        $resolved[$entry->actor_sub] ?? null,
    ),
    $entries,
);
```

Если один и тот же список читается несколькими контроллерами, вынесите
разрешение в общий читающий помощник: вторая реализация рано или поздно
сведётся к обращению внутри цикла.

### Пределы и отказы

- Предел пакета — 100 идентификаторов, значение задаётся установкой.
  Превышение установка **отклоняет, а не усекает**, поэтому длинные списки
  пакет разбивает на части сам.
- Ответы кешируются; кэш сбрасывается сообщением `user.profile.changed`.
- Идентификатор, которому в ответе ничего не соответствует, **отказом
  не является**: приходит `ResolvedUser` с `isResolved: false`, и строка
  выводится с идентификатором вместо имени.

## Данные кросс-сервисной навигации

```php
use Verdeect\IdentityIntegration\Api\NavigationClient;

$navigation = app(NavigationClient::class)->for($sub);  // NavigationData
```

`NavigationData` содержит `items` (список `NavItem`), `profileUrl`, `logoUrl`.
`NavItem` — `id`, `name` (по языкам), `url`, `iconUrl`, `order`.

`iconUrl` — **подписанная ссылка ограниченного срока** на файл SVG. Набора
иконок нет: шрифт пришлось бы подключать в каждом продукте установки.
Отсюда два обязательства продукта:

- **не хранить ответ дольше, чем живёт ссылка.** Срок подписи задаёт установка
  и держит его заметно выше поставляемого часа (`IDENTITY_SERVICES_TTL`),
  предупреждая при сближении. Подняв свой срок, убедитесь, что запас
  сохранился: проверить его со стороны продукта нечем;
- **разрешить origin хранилища в `img-src`** политики содержимого — наряду
  с origin установки, нужным логотипу. Без этого рейл покажет заглушки вместо
  иконок, а причина будет видна только в консоли браузера.

Обновляясь с 0.1, сбрасывать кэш вручную не нужно: состав записи отмечен
в её ключе, и записи прежнего состава просто не читаются. Первую версию 0.2
эта отметка обошла стороной — там записи 0.1 читались как «ссылки не пришло»,
и рейл показывал заглушки вместо иконок до истечения срока кэша. Если вы
обновились на 0.2.0, сбросьте кэш однажды (`php artisan cache:clear`) либо
поставьте 0.2.1 и выше.

Не загрузившаяся иконка — штатный случай: компонент рейла заменяет её первой
буквой имени пункта.

Обычно продукт вызывает клиент не напрямую, а получает готовый состав через
`IdentityProps` (см. [Встраивание](embedding.md)).

- Данные запрашиваются **за одного пользователя при отрисовке страницы**.
- Кэш — по `sub` целиком, **на бэкенде**. Хранение в браузере запрещено.
- Кэш сбрасывается двумя сообщениями: `user.rights.changed`
  и `navigation.changed`.
- Пункты приходят отфильтрованными по роли; своих правил видимости продукт
  не применяет.

## Деградация

Недоступность установки ограничивает **вход** в интерфейс. Уже вошедшие
продолжают работать:

- экраны отрисовываются;
- списки, где не удалось разрешить имена, выводятся **с идентификаторами
  вместо ФИО**, а не отказом;
- рейл при недоступности данных не рисуется вовсе — это допустимое состояние.

Фоновые операции продукта (генерация документов, отчёты) пользовательского
контекста не требуют и от доступности установки не зависят.
