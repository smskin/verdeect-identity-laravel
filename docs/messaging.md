# Сообщения установки и эксплуатация

Установка рассылает сообщения о смене профиля, прав, навигации и о гашении
сессий. Продукт обязан поднять потребителя — иначе кэши устаревают, а вышедший
из установки пользователь продолжает работать в продукте.

## Потребитель

```bash
php artisan identity:consume-events
```

| Опция | Назначение |
| --- | --- |
| `--once` | обработать одно сообщение и выйти (для проверки и прогонов) |
| `--timeout=<с>` | предел ожидания, `0` — без предела |

Команда долгоживущая: под supervisor, systemd или как отдельная служба состава.

```ini
[program:identity-events]
command = php /app/artisan identity:consume-events
directory = /app
user = www-data
numprocs = 1
autostart = true
autorestart = true
```

**Экземпляр один.** Очередь у продукта своя, и второй потребитель лишь делил бы
сообщения между собой, ничего не ускоряя.

Отказ брокера изолирован этой службой и веб-контейнер не роняет: сообщения
накапливаются в очереди, а при восстановлении соединения разбираются.
Переподключение выполняется с нарастающими задержками.

## Что пакет обрабатывает сам

| Сообщение | Что делает пакет |
| --- | --- |
| `user.profile.changed` | сбрасывает кэш профиля и кэш разрешённых имён |
| `user.rights.changed` | сбрасывает кэш данных рейла |
| `navigation.changed` | сбрасывает кэш данных рейла |
| `user.session.terminated` | ставит отметку гашения по `sub` и `sid` |

Всё это работает без единой строки в продукте.

## Гашение сессий: отметка, а не убийство

Обработчик очереди **только помечает**. Сессию гасит **ближайший запрос самого
пользователя**: `EnforceSessionMarks` сверяет возраст его сессии с отметкой
по `sub` и `sid` из его же сессии.

Отсюда два следствия:

1. Обратный индекс «пользователь → его сессии» не нужен, и пакет его не ведёт.
2. Пакет не обращается к хранилищу сессий напрямую — это привязало бы его
   к драйверу. Сессия уничтожается штатным механизмом Laravel.

Подтверждения сообщений **ручные**: отметка ставится до `ack`, иначе падение
между чтением и обработкой потеряло бы гашение сессии.

Дубли возможны — брокер гарантирует доставку «хотя бы один раз», — и на
состояние они не влияют: повторная отметка тем же значением ничего не меняет.

## Очередь продукта

```dotenv
BROKER_EXCHANGE=identity.events
BROKER_QUEUE=<продукт>.identity.events
```

Обменник общий на установку, **очередь у каждого продукта своя**. Пустое имя
очереди — отказ при запуске потребителя, а не работа на очереди соседа:
умолчания у этой настройки нет намеренно.

Метка потребителя в панели брокера выводится из имени очереди; задать явно —
`BROKER_CONSUMER_TAG`.

## Проверка

```bash
# Одно сообщение и выход — видно, что подписка и разбор работают.
php artisan identity:consume-events --once --timeout=30
```

Признаки исправной работы: в журнале продукта появляются записи
`[ConsumeIdentityEventsCommand]`, а смена профиля в установке в течение
`IDENTITY_PROFILE_TTL` отражается в продукте без перезапуска.

Если потребитель не поднят, продукт остаётся работоспособным, но:

- смена имени доезжает только по истечении срока кэша;
- изменение состава пунктов рейла — тоже;
- **выход из установки не гасит сессию продукта** до истечения её срока.
  Это и есть главная причина не откладывать запуск потребителя.
