# Установка и настройка

Продукт установки Verdeect подключает интеграцию с Identity Service одной
зависимостью. Ресурсным сервером продукт не является: его интерфейс обслуживает
только собственный фронтенд, а токены приходят от установки и предъявляются
только ей.

## Требования

| Что | Зачем |
| --- | --- |
| PHP 8.3+, Laravel 13 | Пакет объявляет `illuminate/support` и `illuminate/http` версии 13 |
| Хранилище кэша **с поддержкой блокировок** | Обмен refresh-токена идёт под блокировкой по `sid`; без неё параллельные запросы затрут токен друг друга |
| Сессии Laravel | Аутентификация сессионная, а не токенная |
| RabbitMQ установки | Потребление сообщений о смене профиля, прав и гашении сессий |

Отдельный пакет аутентификации браузера не нужен: Inertia работает на штатной
сессии Laravel.

## Подключение

```bash
composer require verdeect/identity-integration
```

Пакет опубликован в Packagist, исходники —
[smskin/verdeect-identity-laravel](https://github.com/smskin/verdeect-identity-laravel).
Ни объявлять репозиторий в `composer.json`, ни заводить учётные данные
не требуется.

Провайдер обнаруживается автоматически. Маршруты входа и выхода пакет
регистрирует сам — объявлять их в продукте не нужно (см.
[Встраивание](embedding.md)).

Конфигурацию можно опубликовать, но обычно это не требуется — значения
читаются из окружения:

```bash
php artisan vendor:publish --tag=identity-config
```

### Разработка рядом с продуктом

При разработке пакета рядом с продуктом удобнее репозиторий типа `path` —
изменения видны без публикации тега и без ожидания обновления Packagist:

```json
{
    "repositories": [
        { "type": "path", "options": { "symlink": true }, "url": "../identity-integration-php" }
    ]
}
```

## Два клиента, и почему их два

Продукт регистрирует в установке **два конфиденциальных клиента**. Публичным
клиентом продукт установки быть не может.

| Клиент | Поток | Области | Для чего |
| --- | --- | --- | --- |
| Веб-приложение | код авторизации с PKCE | `openid`, `profile` | вход сотрудника, его собственный профиль |
| Служебный | учётные данные клиента | `users:read` | разрешение чужих имён, данные кросс-сервисной навигации |

Одним клиентом обойтись нельзя, и это ограничение содержательное, а не
техническое: `POST /api/users/resolve` разрешает имена **чужих** сотрудников
и пользовательский токен отвергает с `403 insufficient_scope`, а `/userinfo`
по определению возвращает только владельца токена — служебному клиенту области
`openid` и `profile` недоступны, и своё имя через него не получить.

Секрет показывается однократно при регистрации и при перевыпуске. Потерянный
перевыпускается, прежнее значение перестаёт действовать немедленно.

## Переменные окружения

```dotenv
# Адрес установки. Эндпоинты читаются из документа обнаружения
# /.well-known/openid-configuration, а не задаются здесь: между установками
# они могут отличаться.
IDENTITY_BASE_URL=https://id.example.com

# Адреса возврата. Сверяются точным совпадением — регистрируются в установке
# ровно в том виде, в каком заданы здесь.
IDENTITY_REDIRECT_URI=https://product.example.com/auth/callback
IDENTITY_POST_LOGOUT_REDIRECT_URI=https://product.example.com/

# Веб-клиент: вход сотрудника.
IDENTITY_WEB_CLIENT_ID=
IDENTITY_WEB_CLIENT_SECRET=

# Служебный клиент: имена и данные рейла.
IDENTITY_SERVICE_CLIENT_ID=
IDENTITY_SERVICE_CLIENT_SECRET=

# Хранилище кэша пакета. Обязано поддерживать блокировки.
IDENTITY_CACHE_STORE=redis

# Брокер установки. Имена переменных совпадают с identity-service намеренно.
BROKER_HOST=
BROKER_PORT=5672
BROKER_USER=
BROKER_PASSWORD=
BROKER_VHOST=
BROKER_EXCHANGE=identity.events
BROKER_QUEUE=<продукт>.identity.events
```

**Секреты значений по умолчанию не имеют.** Пустой секрет обязан приводить
к внятному отказу, а не к молчаливой работе с чужими учётными данными.

**`BROKER_QUEUE` умолчания тоже не имеет.** Имя очереди принадлежит продукту:
значение из библиотеки увело бы его на очередь соседнего продукта, и потеря
сообщений выяснилась бы по неработающему гашению сессий.

### Необязательные настройки

| Переменная | Умолчание | Что задаёт |
| --- | --- | --- |
| `IDENTITY_DISCOVERY_TTL` | `3600` | срок кэша документа обнаружения |
| `IDENTITY_JWKS_TTL` | `3600` | срок кэша набора ключей |
| `IDENTITY_PROFILE_TTL` | `300` | срок кэша профиля |
| `IDENTITY_RESOLVE_TTL` | `3600` | срок кэша разрешённых имён |
| `IDENTITY_SERVICES_TTL` | `3600` | срок кэша данных рейла |
| `IDENTITY_RESOLVE_BATCH_LIMIT` | `100` | предел пакета разрешения имён |
| `IDENTITY_SESSION_TTL_DAYS` | `90` | предельный срок хранения токенов и отметок |
| `IDENTITY_HTTP_TIMEOUT` | `10` | предел ожидания обращений к установке |
| `IDENTITY_HTTP_RESOLVE` | пусто | подмена узла при соединении, только для разработки |
| `BROKER_CONSUMER_TAG` | из имени очереди | метка потребителя в панели брокера |

Сроки кэшей — страховка, а не механизм актуальности: кэши сбрасываются
сообщениями установки (см. [Сообщения](messaging.md)).

### `IDENTITY_HTTP_RESOLVE` — только для разработки

Подмена узла **при соединении**, то же, что `--resolve` у curl: перечень
записей `узел:порт:адрес` через запятую.

Нужна там, где установка объявляет себя по адресу вроде `http://localhost:81`,
а внутри контейнера `localhost` — сам контейнер. Переписывать узел в адресе
нельзя: он сверяется точным совпадением, — поэтому меняется только то, куда
открывается соединение. В эксплуатации значение пусто, там работает DNS.

## Доверие посреднику

Если TLS завершается на балансировщике, приложение обязано доверять заголовкам
пересылки:

```php
$middleware->trustProxies(at: '*');
```

Без этого приложение видит запрос как `http` и строит `http`-ссылки на
установке, работающей по HTTPS: `redirect_uri` перестаёт совпадать
с зарегистрированным, а cookie сессии с `secure` не доходит до браузера.

Доверять всем адресам допустимо, когда порт приложения не публикуется наружу
и единственный путь к нему — через посредника, который заголовки пересылки
**перезаписывает**, а не дополняет.

## Проверка настройки

```bash
php artisan route:list --path=auth   # /auth/login, /auth/callback, /auth/logout
php artisan config:show identity     # адрес установки, оба клиента, кэш
```

Отсутствие адреса установки **не роняет** загрузку конфигурации: иначе
`php artisan config:cache` падал бы на незаполненном окружении. Отказ
поднимается при первом обращении к установке.
