# Чек-лист интеграции и запреты

Страница для ревью и для агента: короткие проверяемые условия вместо
пересказа. Подробности — по ссылкам.

## Перед первым входом

- [ ] В `composer.json` продукта объявлен репозиторий пакета: приватный
      `vcs` на gitlab.mkomov.com (или `path` при разработке рядом)
- [ ] Доступ к репозиторию заведён под способ подключения: токен `read_api`
      в `auth.json` или `COMPOSER_AUTH` для HTTPS, ключ развёртывания для SSH —
      и в обоих случаях **вне** `composer.json`
- [ ] `composer require verdeect/identity-integration:^0.1`, провайдер обнаружен
      (`php artisan route:list --path=auth` показывает три маршрута)
- [ ] Заданы адрес установки и **оба** клиента с секретами
- [ ] `IDENTITY_REDIRECT_URI` и `IDENTITY_POST_LOGOUT_REDIRECT_URI` совпадают
      с зарегистрированными в установке **точным совпадением**
- [ ] `IDENTITY_CACHE_STORE` указывает на хранилище **с поддержкой блокировок**
- [ ] `BROKER_QUEUE` заполнен именем очереди продукта
- [ ] При TLS на посреднике включено доверие заголовкам пересылки
- [ ] `EnforceSessionMarks` и `RefreshIdentityToken` добавлены в группу `web`
      **в этом порядке**, до middleware разделяемых свойств
- [ ] `RequireIdentitySession` повешен алиасом на экраны продукта,
      но **не** на маршруты `/auth/*`
- [ ] Разделяемые свойства отдают `IdentityProps::share()`
- [ ] Политика содержимого включает `IdentityOrigin::resolve()`
      в `img-src` и `form-action`
- [ ] Потребитель сообщений поднят одним экземпляром под supervisor
- [ ] Кнопка выхода отправляет `POST /auth/logout`

## Запреты

Нарушение любого из них — ошибка интеграции, а не стилистическое замечание.

| Нельзя | Почему |
| --- | --- |
| Писать в `app/` продукта обмен кода, чтение JWKS, хранение токенов, подписку на очередь | Это обязанности пакета; вторая реализация повторит и его ошибки |
| Отдавать токен доступа в браузер (в свойства Inertia, в `<script>`, в API продукта) | Схема Backend-for-Frontend обязательна |
| Извлекать ФИО из ID-токена | Он фиксирует момент входа и свежим не поддерживается; имя берётся из `/userinfo` |
| Хранить снимок имени вместо `sub` | Имя изменяемо, `sub` — нет |
| Связывать учётные записи по адресу электронной почты | Адрес изменяем |
| Вызывать разрешение имён в цикле по строкам списка | Обращение обязано быть пакетным |
| Усекать список идентификаторов до предела пакета | Превышение установка отклоняет, а не усекает; разбиение делает пакет |
| Обращаться к хранилищу сессий напрямую ради гашения | Привязало бы продукт к драйверу; сессию гасит middleware пакета |
| Писать собственный перехватчик истёкшей сессии на фронтенде | Работает штатный механизм Inertia: `409` с `X-Inertia-Location` |
| Применять свои правила видимости к пунктам рейла | Они приходят отфильтрованными; второе правило разойдётся с первым |
| Копировать Vue-компоненты рейла в продукт | Эталон живёт в npm-пакете; копия разойдётся на первой правке |
| Использовать `/revoke` для выхода | Он не выводит человека из установки — возврат одним кликом без пароля |
| Поднимать второй экземпляр потребителя сообщений | Они лишь поделят очередь между собой |

## Признаки исправной интеграции

- Неаутентифицированный запрос экрана уходит на `route('identity.login')`.
- Запрос Inertia с истёкшей сессией получает `409` и заголовок
  `X-Inertia-Location`.
- В разделяемых свойствах есть `identity.profile` и `identity.crossService`
  и **нет** ничего похожего на токен.
- Заголовок `Content-Security-Policy` содержит origin установки
  в `img-src` и `form-action`.
- Страница со списком, где тридцать разных авторов, даёт **одно** обращение
  к `/api/users/resolve`.
- Выход из установки в другом продукте гасит сессию здесь — ближайшим
  запросом пользователя.

## Когда установка недоступна

Ожидаемое поведение, а не поломка:

- вошедшие продолжают работать;
- имена, которые не удалось разрешить, выводятся идентификаторами;
- рейл не рисуется;
- **вход невозможен** — это единственное, что ограничивается.

Если продукт при недоступности установки отдаёт ошибку на экранах — интеграция
сделана неверно.
