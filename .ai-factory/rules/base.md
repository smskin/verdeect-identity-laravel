# Базовые правила проекта

> Соглашения выведены разбором кодовой базы пакета. Правьте по мере надобности.

## Границы пакета

Нарушение любого из четырёх пунктов — ошибка, а не стилистическое замечание.

- **`App\` в `src/` не встречается.** Проверяется набором
  `tests/Feature/ProviderTest.php` перебором файлов и образцом
  `~\bApp\\\\[A-Z]~`. Ссылка на пространство имён приложения привязала бы
  библиотеку к одному продукту.
- **Продуктовых деталей в коде нет.** Имена очередей, селекторы разметки,
  адреса установок — только настройка или параметр. У значения, принадлежащего
  продукту, умолчания в библиотеке быть не должно: молчаливое умолчание
  уведёт продукт на чужую очередь.
- **Компоненты интерфейса пакет не публикует.** Они живут в npm-пакете
  `@verdeect/identity-integration-vue`. В `publishes()` только настройка.
- **Решение остаётся продукту.** Пакет предоставляет сборку и вычисление
  (`IdentityProps`, `IdentityOrigin`), но не подменяет middleware продукта
  и не составляет за него политику содержимого.

## Соглашения именования

- Файлы: `PascalCase.php`, один класс на файл, путь повторяет пространство
  имён (`src/Tokens/TokenSet.php` → `Verdeect\IdentityIntegration\Tokens\TokenSet`).
- Классы: `PascalCase`. Интерфейсы — с приставкой `I`
  (`IUserResolver`, `IDiscoveryClient`, `IJwksProvider`, `IProfileDecorator`,
  `IIdentityEventHandler`).
- Пустые реализации точек расширения — с приставкой `Null`
  (`NullProfileDecorator`, `NullIdentityEventHandler`).
- Отказы — с окончанием `Exception`, все наследуют `IdentityException`.
- Методы и свойства: `camelCase`. Константы: `UPPER_SNAKE_CASE`,
  по умолчанию `private const`.
- Ключи настройки и переменные окружения: `snake_case` и `UPPER_SNAKE_CASE`.
  Имена `BROKER_*` намеренно совпадают с identity-service.
- Функции тестовой оснастки: обязательная приставка `identity`
  (`identityFakeHttp`, `identityIdToken`). Pest объявляет функции глобально,
  и одноимённая в другом наборе уронит весь прогон.

## Структура

```
src/
  Api/          клиенты прикладного интерфейса установки и их DTO
  Discovery/    документ обнаружения, JWKS, проверка ID-токена
  Events/       потребитель сообщений, отправка обработчику, отметки гашения
  Exceptions/   отказы интеграции, общий предок IdentityException
  Flow/         начало потока кода авторизации, пара PKCE
  Http/         контроллеры, middleware, внешнее перенаправление
  Inertia/      сборка разделяемых свойств
  Profile/      профиль пользователя, формы имени, точка расширения
  Session/      чтение сессии входа
  Support/      настройка, кэш, HTTP-клиент, вычисление origin
  Tokens/       хранилище, обмен, выдача действующего токена
config/identity.php    единственный файл настройки, публикуется группой identity-config
routes/identity.php    маршруты входа, возврата и выхода
testing/helpers.php    оснастка прогонов, уходит в поставку через autoload.files
tests/                 Feature и Unit, в поставку не входит
```

- Ровно один провайдер — `src/IdentityServiceProvider.php`. Привязки
  объявляются в нём и нигде больше.
- Обращение к кэшу идёт только через `IdentityCache`, к настройке — только
  через `IdentityConfig`, к HTTP — только через `IdentityHttp`.
  Прямых `Cache::`, `config()` и `Http::` в остальных классах быть не должно.

## Код

- `declare(strict_types=1);` в каждом файле, сразу после `<?php`.
- Классы — `final`; неизменяемые DTO — `final readonly class`.
  Абстрактным остаётся только `IdentityException`.
- Типы у всех параметров, возвратов и свойств. Обобщения массивов —
  в докблоке (`@return list<string>`, `@param array<string, mixed> $payload`).
- Объединение с `null` пишется как `Type|null`, **не** `?Type`.
- Зависимости — через продвинутые свойства конструктора
  (`private readonly Foo $foo`). Контейнер собирает их сам.
- Вызовы с четырьмя и более доводами — именованными доводами.
- Строки в одинарных кавычках, склейка через `.`. Двойные кавычки —
  только там, где нужна подстановка в тексте отказа.
- Первым делом в методе — сторожевые проверки и ранние `return`;
  основной путь остаётся на верхнем уровне. Глубокой вложенности избегать.

## Комментарии и докблоки

Стиль выдержан во всём пакете; его нужно сохранить.

- Комментарии и докблоки — **по-русски**.
- Докблок объясняет **причину**, а не пересказывает код: почему ключом взят
  `sid`, почему отметка — время, а не снимаемый признак, почему выход `POST`.
  Докблок вида «Возвращает токен» бесполезен и его писать не нужно.
- Докблок обязателен на классе. На методе — когда есть что объяснить сверх
  сигнатуры либо нужны обобщения массивов.
- Ссылки на источник решения (`справка 9, пункт 3`, `PRD 12.2`,
  `критерий 86`) сохраняются: по ним восстанавливается обоснование.

## Отказы

- Все отказы пакета наследуют `IdentityException`, чтобы продукт отличал
  их одним `catch`.
- Незаполненная настройка — `ConfigurationException::missing($key)`
  с указанием ключа. Порождается при первом обращении, **не** на загрузке
  провайдера: иначе `php artisan config:cache` валился бы на пустом окружении.
- Именованные конструкторы отказов — статические методы
  (`ConfigurationException::missing()`).
- Недоступность установки не роняет страницу: документ обнаружения отдаётся
  из устаревшего кэша, неразрешённые `sub` возвращаются как есть, выход
  выполняется локально.

## Журналирование

- Через фасад `Log`.
- Первым в сообщении идёт `[Класс.метод]`, дальше текст по-английски строчными:
  `Log::warning('[CallbackController] state mismatch')`.
- Уровни: `debug` — успешный ход, `warning` — восстановимое отклонение,
  `error` — отказ.
- Подробности — вторым доводом массивом.
- Адрес установки в журнал попадает; **секреты клиентов, токены и коды
  не журналируются никогда**.

## Прогон

- Pest 5 поверх `orchestra/testbench` 11. `tests/TestCase.php` регистрирует
  провайдер вручную: внутри собственного репозитория обнаружения Composer нет.
- Базы данных нет и `RefreshDatabase` не подключается.
- Обращения к установке перехватывает `Http::fake()` оснасткой из
  `testing/helpers.php`. `Http::fake()` при повторном вызове образцы
  не заменяет, а дополняет, и первый совпавший выигрывает — поэтому образец
  объявляется один раз за набор, а не в `beforeEach` с переопределением.
- Окружение прогона задано в `phpunit.xml` и из окружения разработчика
  не берётся: адреса возврата сверяются точным совпадением.
- Новую оснастку класть в `testing/`, а не в `tests/`: `tests/` в архив
  Composer не входит, и наборам продукта такая оснастка будет недоступна.
- Перед сдачей работы — `composer ci:check` (PHPStan уровня 7, затем прогон).
  Уровень не снижается и предупреждения не подавляются.
