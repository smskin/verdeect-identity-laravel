# Соглашения пакета verdeect/identity-integration

Это **библиотека Composer**, а не приложение. Своего `app/`, базы данных,
миграций и фронтенда здесь нет и не появится. Всё, что верно для продукта
установки, здесь неверно по умолчанию.

Полный свод — `.ai-factory/rules/base.md`. Здесь то, что нужно держать в голове
в момент написания кода.

## Границы: проверять первыми

Четыре правила. Нарушение любого — ошибка, а не замечание по стилю.

### 1. `App\` в `src/` не встречается

Проверяется набором `tests/Feature/ProviderTest.php`: он перебирает файлы
`src/` и ищет образец `~\bApp\\\\[A-Z]~`. Ссылка на пространство имён
приложения привязала бы библиотеку к одному продукту и обнаружилась бы только
при установке во второй.

Значит: ни `App\Models\User`, ни `App\Enums\...`, ни строкой в докблоке.
Нужен тип из продукта — объявляйте интерфейс в пакете и пусть продукт
привязывает свою реализацию.

### 2. Продуктовых деталей в коде нет

Ни имён очередей, ни селекторов разметки, ни адресов конкретной установки.
Всё такое — ключ настройки либо параметр метода.

**У значения, принадлежащего продукту, умолчания в библиотеке быть не должно.**
`BROKER_QUEUE` умолчания не имеет намеренно: строка из библиотеки увела бы
продукт на очередь соседа молча. Пустое значение обязано приводить к внятному
отказу.

Прежде чем зашить строку, спросите: сработает ли это во **втором** продукте?

### 3. Компоненты интерфейса пакет не публикует

Рейл навигации и блок пользователя живут в npm-пакете
`@verdeect/identity-integration-vue` и приходят продукту зависимостью.
В `publishes()` только настройка, группой `identity-config`. Копий в
`resources/` не заводить: опубликованная копия разошлась бы с эталоном
на первой же правке.

### 4. Решение остаётся продукту

Пакет **не уничтожает сессии сам** и **не составляет политику содержимого**.
Он даёт middleware и вычисления — `IdentityProps::share()`,
`IdentityOrigin::resolve()`, — а состав разделяемых свойств и набор директив
принадлежат приложению.

Токены наружу не выходят никогда: схема Backend-for-Frontend обязательна,
в браузер уходят имя пользователя и готовые данные рейла.

## Структура

```
src/
  Api/          клиенты прикладного интерфейса установки и их DTO
  Discovery/    документ обнаружения, JWKS, проверка ID-токена
  Events/       потребитель сообщений, отправка обработчику, отметки гашения
  Exceptions/   отказы, общий предок IdentityException
  Flow/         начало потока кода авторизации, пара PKCE
  Http/         контроллеры, middleware, внешнее перенаправление
  Inertia/      сборка разделяемых свойств
  Profile/      профиль, формы имени, точка расширения
  Session/      чтение сессии входа
  Support/      настройка, кэш, HTTP-клиент, вычисление origin
  Tokens/       хранилище, обмен, выдача действующего токена
```

Ровно один провайдер — `src/IdentityServiceProvider.php`. Привязки объявляются
в нём и нигде больше.

**Единственные точки доступа наружу:**

| Ресурс | Единственная точка | Прямо использовать нельзя |
|---|---|---|
| Кэш | `Support\IdentityCache` | `Cache::`, `cache()` |
| Настройка | `Support\IdentityConfig` | `config()` |
| HTTP | `Support\IdentityHttp` | `Http::` |

`IdentityCache` держит общий префикс `identity:`: содержимое видно одной
командой `KEYS identity:*`, а очистка не задевает чужого.

## Код

- `declare(strict_types=1);` в каждом файле, сразу после `<?php`.
- Классы — `final`. Неизменяемые DTO — `final readonly class`.
  Абстрактным остаётся только `IdentityException`.
- Типы у всех параметров, возвратов и свойств. Обобщения массивов —
  в докблоке: `@return list<string>`, `@param array<string, mixed> $payload`.
- Объединение с `null` — **`Type|null`**, не `?Type`:

  ```php
  public function keyFor(string|null $kid): JWK        // так
  public function keyFor(?string $kid): JWK            // не так
  ```

- Зависимости — продвинутыми свойствами конструктора:

  ```php
  public function __construct(
      private readonly IdentityCache $cache,
      private readonly IdentityConfig $config,
  ) {}
  ```

- Вызовы с четырьмя и более доводами — именованными доводами.
- Строки в одинарных кавычках, склейка через `.`:

  ```php
  $url = $this->config->baseUrl().'/api/users/resolve';
  ```

  Двойные кавычки — только там, где нужна подстановка в тексте отказа.
- Сторожевые проверки и ранние `return` идут первыми; основной путь остаётся
  на верхнем уровне.

## Именование

- Интерфейсы — с приставкой `I`: `IUserResolver`, `IDiscoveryClient`,
  `IJwksProvider`, `IProfileDecorator`, `IIdentityEventHandler`.
- Пустые реализации точек расширения — с приставкой `Null`:
  `NullProfileDecorator`, `NullIdentityEventHandler`.
- Отказы — окончание `Exception`, предок `IdentityException`.
- Константы класса — `private const UPPER_SNAKE_CASE`, если не нужны снаружи.
- Пути прикладного интерфейса — `private const PATH` в классе клиента.

## Докблоки и комментарии

Стиль выдержан во всём пакете; сохраняйте его.

- Пишутся **по-русски**.
- Объясняют **причину**, а не пересказывают код.

  ```php
  /**
   * Хранилище токенов, ключ — `sid`.
   *
   * Ключом служит идентификатор сессии входа, а не сессии Laravel: один
   * человек в двух браузерах даёт две сессии входа и два `sid`, и общий
   * ключ заставил бы их затирать refresh-токен друг друга.
   */
  ```

  Докблок вида «Возвращает токен» бесполезен — не писать.
- Обязателен на классе. На методе — когда есть что объяснить сверх сигнатуры
  либо нужны обобщения массивов.
- Ссылки на источник решения (`справка 9, пункт 3`, `PRD 12.2`,
  `критерий 86`) сохраняются: по ним восстанавливается обоснование.
- Развёрнутое пояснение внутри метода — блочным комментарием `/* … */`,
  на классе — `/** … */`.

## Отказы

- Все наследуют `IdentityException` — продукт отличает их одним `catch`.
- Именованные конструкторы — статические методы:
  `ConfigurationException::missing($key)`.
- Незаполненная настройка читается через `IdentityConfig::required()`
  и даёт внятный текст с указанием ключа.
- **Отказ поднимается при первом обращении, не на загрузке провайдера.**
  Иначе `php artisan config:cache` валился бы на пустом окружении.
- Недоступность установки не роняет страницу: документ обнаружения отдаётся
  из устаревшего кэша, неразрешённые `sub` возвращаются как есть, выход
  выполняется локально.

## Журналирование

```php
Log::warning('[CallbackController] state mismatch');
Log::debug('[JwksProvider.keyFor] unknown kid, refreshing', ['kid' => $kid]);
```

- Через фасад `Log`.
- Первым идёт `[Класс]` или `[Класс.метод]`, дальше текст по-английски
  строчными.
- `debug` — успешный ход, `warning` — восстановимое отклонение,
  `error` — отказ.
- Подробности — вторым доводом массивом.
- Адрес установки в журнал попадает. **Секреты клиентов, токены, коды
  и refresh-токены не журналируются никогда.**

## Состязания

Обмен токенов и перечитывание JWKS идут **под блокировкой** с повторной
проверкой состояния после её получения. Без этого параллельные запросы Inertia
предъявят установке прежний refresh-токен, она распознает это как кражу
и отзовёт всё семейство. Ключ блокировки — по `sid`.

Добавляя обращение к внешнему ресурсу с записью в общий кэш, повторите этот
приём, а не изобретайте свой.

## Настройка

- Единственный файл — `config/identity.php`, сливается через
  `mergeConfigFrom()`.
- **Адресов эндпоинтов там нет**: они читаются из документа обнаружения
  установки. Исключение — пути прикладного интерфейса, в документ обнаружения
  не входящие; они живут константами в классах клиентов.
- Секреты умолчаний не имеют.
- Каждый неочевидный ключ сопровождается комментарием с причиной.
- Новый ключ добавляется парой: запись в `config/identity.php` и метод-читатель
  в `IdentityConfig`.
